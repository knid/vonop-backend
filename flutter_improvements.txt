⏺ Mobile App Creation Process — Full Audit Report

  Architecture Overview

  The system has two mobile app creation systems:

  - System A (Legacy Native): URL-wrapper mobile apps → APK/IPA via Flutter
  template → deploy to stores
  - System B (Modern AI Builder): AI-generated Next.js apps → Flutter build →
  deploy to stores

  Both use Asynq (Redis) to dispatch tasks to external Go workers
  (android-worker, ios-worker).

  ---
  CRITICAL BUGS & SECURITY ISSUES

  1. Hardcoded AWS/Redis Credentials in .env files (BOTH WORKERS)

  Both .env and .env.dev contain real AWS keys, Redis passwords, and API secrets
   in plaintext tracked by git.

  2. Path Traversal in Android Deploy (deploy.go:42)

  BuildID used directly in path construction without validation:
  constants.PROJECT_TEMP_PATH + deployPayload.BuildID. Locale is validated but
  BuildID is not.

  3. Unvalidated S3 Service Account Path (Android deploy.go:48)

  ServiceAccountPath from payload used directly as S3 key — could download
  arbitrary files from the bucket.

  4. iOS IPA Upload Path Mismatch (build.go:91-95)

  Uploads Payload.zip but names it .ipa. Downstream sign task expects .ipa
  format — potential silent corruption.

  5. iOS Bundle Name Extraction Will Panic (sign.go:26)

  strings.Split(signPayload.PackageName, ".")[2] — panics on package names with
  fewer than 3 parts (e.g., com.app).

  6. P8 Keys Downloaded to Temp Without Secure Deletion (iOS)

  P8 keys stored as plaintext temp files, cleaned only by rm -rf (recoverable
  with forensics). File permissions not restricted.

  7. Keystore Credentials Written with 0644 Permissions (Android build.go:304)

  Keystore passwords in world-readable properties file. Should be 0600.

  8. iOS Type Assertions Without Nil Checks (sign.go:135-136)

  Plist type assertions panic if structure is unexpected — no bounds checking.
