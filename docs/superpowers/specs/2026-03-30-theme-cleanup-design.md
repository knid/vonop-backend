# Theme Cleanup: Fix Encoding, Remove Dead Code, Remove Redundancy

**Date:** 2026-03-30
**Status:** Approved

## Problem

`AppTheme` is stored as a JSONB `[]byte` blob on `AppProject`. The actual useful data is ~200 bytes (6 hex colors + 2 font names), but due to a recursive base64 encoding bug, some rows balloon to 52KB. The struct also carries 3 unused fields (`DarkColorScheme`, `Spacing`, `BorderRadius`), and the theme data is redundantly stored in 3 places (DB column, `_wemob/theme.json` in git, and materialized into `globals.css`).

### Encoding Bug Root Cause

`Theme` is declared as `[]byte` with `bun:",type:jsonb"`. Go's `json.Marshal` base64-encodes `[]byte` values. On each read→update cycle through Bun ORM, another base64 layer wraps the data. Projects that have been updated multiple times accumulate 5-6+ layers of encoding.

### Data Size Distribution (current)

| Bucket | Count | Avg bytes |
|--------|-------|-----------|
| tiny (<100B) | 36 | 16 |
| normal (100-500B) | 16 | 303 |
| medium (500B-2KB) | 30 | 949 |
| large (2-10KB) | 13 | 4,622 |
| huge (>10KB) | 13 | 27,126 |

## Design

### 1. Slim down `AppTheme` struct

Remove unused fields from `models.AppTheme`:

```go
// Before
type AppTheme struct {
    ColorScheme     map[string]any `json:"color_scheme"`
    DarkColorScheme map[string]any `json:"dark_color_scheme,omitempty"`
    Typography      map[string]any `json:"typography,omitempty"`
    Spacing         map[string]any `json:"spacing,omitempty"`
    BorderRadius    map[string]any `json:"border_radius,omitempty"`
}

// After
type AppTheme struct {
    ColorScheme map[string]any `json:"color_scheme"`
    Typography  map[string]any `json:"typography,omitempty"`
}
```

**Fields removed:**
- `DarkColorScheme` — passed through the entire pipeline but never consumed. `buildGlobalsCSSTheme` accepts it as a parameter but ignores it. The builder prompt says "Light theme only — no dark mode overrides."
- `Spacing` — never generated by structure prompts, never read by any code.
- `BorderRadius` — never generated by structure prompts, never read by any code.

Also remove `DarkColorScheme` from `appFileStructure` (the struct returned by `PlanAppFileStructure`).

### 2. Fix the encoding bug

Change `Theme` field type in `AppProject` and `AppSnapshot` models from `[]byte` to `json.RawMessage`:

```go
// Before
Theme []byte `bun:",type:jsonb,default:'{}'"`

// After
Theme json.RawMessage `bun:",type:jsonb,default:'{}'"`
```

`json.RawMessage` is `[]byte` under the hood, but `json.Marshal` treats it as pre-encoded JSON — no base64 wrapping. This prevents future re-encoding on read→update cycles.

**Data migration:** A one-time script (`cmd/fix_theme_encoding/main.go`) that:
1. Selects all `app_projects` where `octet_length(theme::text) > 500`
2. Recursively decodes base64 layers until clean JSON is reached
3. Strips the removed fields (`dark_color_scheme`, `spacing`, `border_radius`) from the JSON
4. Updates the row with clean JSON
5. Does the same for `app_snapshots`

### 3. Remove redundant theme from LLM context

In `buildProjectContext` and `buildProjectContextForChat` (`app_builder_context.go`), remove the block that unmarshals `project.Theme` and writes `Theme: %v` to the LLM system prompt.

**Rationale:** The LLM already sees the resolved colors inside the pre-injected `globals.css` file (which contains all `@theme` color tokens). The builder prompt explicitly says "Do NOT write app/globals.css — it is pre-injected with the project's color scheme." The raw Go map dump is redundant and poorly formatted (`map[color_scheme:map[primary:#hex ...]]`).

### 4. Remove theme from API response

Remove `Theme map[string]any` from `responses.AppProjectResponse`. The frontend does not consume this field.

Remove all `var theme map[string]any` + `json.Unmarshal(project.Theme, &theme)` blocks in `app_views.go` that exist solely to populate the response.

### 5. Remove theme from git repo

- Remove `WriteTheme` and `ReadTheme` calls throughout the codebase (the methods on `gitrepo.Repo` can stay for now but will have no callers)
- Stop writing `_wemob/theme.json` in `app_builder_controller.go` (commit flow) and `app_project_controller.go` (snapshot flow)
- Remove theme restoration from git in `RestoreAppSnapshot` — theme persists in the DB column

### 6. Clean up downstream function signatures

Remove the `darkColorScheme` parameter from:
- `buildGlobalsCSSTheme(colorScheme, darkColorScheme, isMobile)` → `buildGlobalsCSSTheme(colorScheme, isMobile)`
- `buildEcommerceGlobalsCSSTheme(colorScheme, darkColorScheme)` → `buildEcommerceGlobalsCSSTheme(colorScheme)`
- `getTemplateContent(path, colorScheme, darkColorScheme, projectType, dataModels)` → drop `darkColorScheme`
- `getTemplateContentWithLang(path, colorScheme, darkColorScheme, projectType, dataModels, lang)` → drop `darkColorScheme`

Remove `DarkColorScheme` assignments in:
- `app_builder_generation.go` (lines ~295, ~598) — where `themeData` is constructed
- `app_views.go` (line ~72) — screenshot-to-structure flow

No prompt changes needed — the structure planning prompts in `ai_structure.go` don't ask the LLM to generate `darkColorScheme`.

- Structure planning prompts — they don't reference `darkColorScheme`
- `buildGlobalsCSSTheme` internal logic — it never used `darkColorScheme` anyway, just removing the parameter
- `gitrepo.Repo.WriteTheme` / `ReadTheme` methods — remove since they will have no callers after cleanup
